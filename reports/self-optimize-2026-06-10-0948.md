## 详细借鉴点

### 1. 多工具适配器生成管线：从共享规格到各平台安装脚本
- 来源: [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents) (channel: github)
- 相关性: agency-agents 实现了 convert.sh + install.sh，能从共享 agent 定义自动生成 Claude Code / Cursor / Codex / Copilot 等多个平台的安装文件；AI Memory OS 已有 adapters/ 目录和 skills/registry.json，但缺少自动生成各平台 skill 外壳的管线。
- 接入设想: 新增 tools/convert-adapters.sh（参考其 convert.sh 模式），从 skills/registry.json + skills/<skill>/SKILL_SPEC.md 生成 adapters/claude/skills/、adapters/codex/skills/ 等目录下的各平台 skill 文件。
- 工作量 / 价值: M / high
- 风险: 当前 skill 数量不多，管线收益需达到临界量；需维护模板版本与各平台能力差异的映射。
- 验证: fits=true, 仓库已有 tools/sync-skills.ps1 和 adapters/，生成管线是同步脚本的自然延伸，能降低多平台维护成本。

### 2. 智能体描述结构：Personality + Workflow + Deliverables 三层模型
- 来源: [msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents) (channel: github)
- 相关性: agency-agents 每个 agent 文件包含 identity、core mission、workflows、deliverables、success metrics 等结构化字段；AI Memory OS 的 SKILL_SPEC.md 当前是自由格式，可借鉴该分层结构提升 skill 规范的一致性和可读性。
- 接入设想: 优化 skills/<skill>/SKILL_SPEC.md 模板（templates/ 目录），增加 identity/mission/workflow/deliverables/metrics 等可选字段结构。
- 工作量 / 价值: S / med
- 风险: 结构化过度可能增加 skill 编写负担，需保持字段可选、渐进增强。
- 验证: fits=true, SKILL_SPEC.md 当前是自由格式，引入可选结构化字段可提升 skill 一致性和可读性，且不破坏现有内容。

- 验证: fits=true, 学习的闭环与复盘触发机制直接对应本仓库的 proposal 审核晋升流程，且已有 safety-rules 防止自动化绕过人工审核。
