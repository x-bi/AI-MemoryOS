## 详细借鉴点

### 1. 按适配器的预算账本与成本熔断机制
- 来源: [paperclipai/paperclip](https://github.com/paperclipai/paperclip) (channel: github)
- 相关性: Paperclip 对每个 agent 设月度预算并在超额时停摆；Memory OS 目前只有临时性的「Claude 预算更充足」口头判断，缺少可审计的每适配器用量账本与熔断规则。
- 接入设想: 可沉淀为 workflows/ 下的成本监控流程或 logs/ 下的预算审计模板，并在 router/ 路由策略中以预算信号影响 L1/L2 偏置；不触碰 proposals/。
- 工作量 / 价值: M / med
- 风险: 实际用量数据来自外部账单，Memory OS 本地难以自动采集，可能沦为静态文档而非可执行规则。
- 验证: fits=false, 本仓库无运行时亦无外部账单采集，每适配器用量账本与熔断无法执行，只能沦为静态文档，与其可审计可执行目标背离。

### 2. 每任务可追溯的不可变审计票据

- 风险: 票据粒度过细会放大 logs/ 体积并干扰既有 Final Trace 轻量审计约定。
- 验证: fits=unclear, 与现有 Final Trace 轻量审计约定冲突，按 L2/L3 决策逐条建票据会放大 logs/ 体积，价值与粒度需再权衡。

### 3. 任务后自学习反馈回路：成功模式自动浮现为捕获候选
- 来源: [ruvnet/ruflo](https://github.com/ruvnet/ruflo) (channel: github)
- 相关性: ruflo 的核心架构是 Router→Swarm→Agents→Memory→Learning Loop 的闭环，hooks 在任务完成后自动从成功执行中学习并跨会话记忆，与 Memory OS 的 router + L3 捕获 + memory-curator 目标高度同构，但 Memory OS 目前缺少显式的「任务后反馈」环节。
- 接入设想: 可作为新 workflow 落入 workflows/（如 learning-loop.md），并与 skills/memory-curator/、router/skill-map.md 联动：任务收尾时由轻量 hook 触发 L1 反思，仅把高置信度「可复用模式/反模式」作为候选提交给用户确认，不自动写入。
