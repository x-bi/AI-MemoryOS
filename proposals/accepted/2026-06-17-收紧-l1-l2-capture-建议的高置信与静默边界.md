# Proposal: 收紧 L1/L2 capture 建议的高置信与静默边界

## Summary

将 L1/L2 capture 建议从"类型命中即可建议"收紧为高置信、有本次任务证据、当前上下文未覆盖/未拒绝、能减少未来错误才建议；L1/L2 不为查重额外读取 Memory OS，用户确认后才进入 L3 查重并写 pending。

## Scope

- Global / domain / stack / project-specific: Global adapter gate behavior.
- Applies to: Claude / Codex L1/L2 capture suggestion behavior, especially post-task lightweight reflection and boundary-risk findings.
- Does not apply to: L3 proposal writing after explicit user confirmation, formal proposal promotion workflow, or ordinary Memory OS duplicate checks during explicit maintenance mode.

# 收紧 L1/L2 capture 建议的高置信与静默边界

## Context

当前 Claude gate 已有 L1/L2 capture triggers：仅对 `反模式：`、`路由纠正：`、`可复用模式：`、`重复失败模式：`、`边界险触：` 这五类 typed reusable findings 建议 capture，并要求一句话建议、用户确认后才写 pending、拒绝后不再重复追问。

本次讨论发现：现有规则已经覆盖"用户拒绝后不再追问"，但没有显式覆盖以下边界：

- 如果当前上下文已显示该内容已有等价规则、已被用户判定不做、已拒绝、或只是重复表达，应静默。
- L1/L2 不应为了判断 capture 是否重复而额外扩大 Memory OS 读取或扫描。
- "非重复"应优先理解为基于当前任务与已读上下文的明显非重复；真正查重应在用户确认 capture、进入 L3 后进行。

## Reusable lesson

L1/L2 capture 建议应是低频、高置信的输出抑制机制，而不是每次任务后的显式复盘流程。只有当发现属于既定五类 capture 类型、具备本次任务证据、当前上下文未显示已覆盖/已拒绝/已判定不落地，并且能明确减少未来重复错误、路由/技能误触发或边界风险时，才建议创建 pending proposal；不确定时保持静默。

## Proposed Memory OS change

建议在 adapter gate 的 L1/L2 capture trigger 规则源中补充以下语义，并同步生成 Claude / Codex gate：

```text
L1/L2 capture suggestions are high-confidence only. Suggest capture only when the finding fits one of the typed capture categories, is evidence-backed by the current task, is not already covered, rejected, or judged out-of-scope in the current context, and is likely to reduce future repeated mistakes, routing/skill misfires, or boundary risk. Do not expand Memory OS reads only to look for capture duplicates during L1/L2; perform duplicate checks only after the user confirms capture and the task enters L3. When uncertain, stay silent.
```

可选中文表述：

```text
L1/L2 capture 建议仅限高置信场景。只有当发现属于既定 capture 类型、有本次任务证据、当前上下文未显示已覆盖/已拒绝/已判定不落地，并且能减少未来重复错误、路由/技能误触发或边界风险时，才建议 capture。L1/L2 不为查重额外扩大 Memory OS 读取；用户确认 capture、进入 L3 后才执行查重。不确定时保持静默。
```

落地时应修改 gate 共享源或相应 adapter overlay，而不是手改生成目标；同时按 change companions 完成 adapter gate 同步与校验。

## Safety and sensitivity check

本 proposal 不包含 token、密码、PII、生产日志、客户私有代码或敏感业务数据。它只调整 Memory OS capture 建议的触发/抑制边界，不授权自动写入正式规则，也不改变 pending-first 的写入隔离原则。

## Source task or evidence summary

来源于 2026-06-17 对 `reports/self-optimize-2026-06-17-1556.md` 的复盘讨论。用户指出：现有 capture 边界已经依赖模型在对话末尾判定；如果只是增加几个反问问题价值不大。进一步讨论明确：有价值的改进不是新增 checklist，而是将 capture 建议收紧为"高置信、有证据、非重复、能减少未来错误才建议；否则静默"，并明确 L1/L2 不为查重额外读取 Memory OS。

## Risks

- 是否过度泛化：低。该规则只收紧 L1/L2 capture suggestion 的输出条件，不扩大 L3 写入权限，也不改变 pending-first 的写入隔离原则。
- 是否包含敏感信息：无。内容只描述 Memory OS capture 建议边界，不包含 token、密码、PII、生产日志、客户私有代码或敏感业务数据。
- 是否与现有规则冲突：无。它补充现有 typed capture triggers 的抑制条件，而不是替换五类 trigger 或改变用户确认后才写 pending 的规则。
