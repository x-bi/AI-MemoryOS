# Proposal: 新增文件删除安全守则——默认回收站、禁用绕过命令

## Summary

在 shared gate-core 增补一条 `File Deletion Safety` 守则（本条当前只针对 Windows 环境）：删除项目源码、配置或用户文件/目录时默认走系统回收站；禁止 `rm`/`del`/`Remove-Item`/`rd`/`rmdir` 等绕过回收站的命令；优先使用可进回收站的 PowerShell（先 `Add-Type -AssemblyName Microsoft.VisualBasic`，再调用 `[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile/DeleteDirectory(..., 'OnlyErrorDialogs', 'SendToRecycleBin')`）；无法确认删除方式是否进回收站时先问用户；构建/测试/缓存产物清理与 git 删除沿用既有规则，不重复约束。

## Scope

- Global / domain / stack / project-specific: Global shared gate behavior.
- Applies to: Claude 与 Codex 两个适配器（shared source 渲染），所有删除项目源码、配置或用户文件/目录的动作，不受 L0-L3 分类影响。本条当前只针对 Windows 环境（PowerShell `Microsoft.VisualBasic.FileIO.FileSystem` 的 `SendToRecycleBin` 仅 Windows 可用）；非 Windows 环境暂不受本条约束。
- Does not apply to: 路径受限的构建/测试/缓存等非交付产物清理（由 `Verification` 段覆盖）；`git clean` / `git rm` / `git checkout -- <path>` / `git reset --hard` 等 git 删除（由 git 操作边界规则覆盖）。`proposals/` / `logs/` 等 Memory OS 自身写入入口的常规写入不属于删除动作；若删除这些目录下的文件，仍按本条或 proposal-promotion 流程处理。

## Rationale

### Context

当前 gate 已有两条与删除相关的边界：

- `Read And Write Boundaries`：不执行 git 操作（commit/push/.../clean/checkout with path/reset 等）除非用户明确提及；本仓库共享，隐式 git 变更影响所有适配器和用户。
- `Verification`：清理构建/测试/缓存产物前约束路径，不自动清理源码、lockfile、snapshot、generated、API type 文件。

但 **没有覆盖普通文件系统删除命令**：`rm`、`del`、`Remove-Item`、`rd`/`rmdir` 都绕过回收站，永久删除。Git Bash 下的 `rm` 在 Windows 上同样永久删除，而非进回收站。agent 在"清理临时文件""删旧实现""移除废弃配置"等场景下若直接用这些命令，会造成不可逆丢失，且不受既有两条规则约束。

### 优化点（相对用户原始三句规则）

用户原稿三条：默认回收站、禁用 `rm`/`del`/`Remove-Item`、不确定先问。方向正确，但直接落地有三处问题：

1. **缺合规路径**：只禁不给替代，agent 只能每次都问，规则退化为纯禁止。补 PowerShell `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile/DeleteDirectory(..., 'OnlyErrorDialogs', 'SendToRecycleBin')`（调用前先 `Add-Type -AssemblyName Microsoft.VisualBasic`）作为推荐方式。
2. **与既有规则交叉未厘清**：`git clean` / `git checkout --` / `git reset --hard` 也永久删文件，但已被 git 边界覆盖；构建/缓存产物清理已在 `Verification` 段允许。本条应声明这两处豁免，避免双重管辖或互相架空，也避免把 `node_modules`/`dist` 大目录塞进回收站。
3. **"默认回收站"与"不确定先问"张力**：应明确"优先用回收站方式；无回收站方式时再问"，而非两条并列。

### 与既有规则的关系

- 不冲突 `Read And Write Boundaries` 的 git 边界：git 删除仍按 git 规则（需用户明确提及），本条只管文件系统删除命令。
- 不冲突 `Verification` 的产物清理：路径受限的缓存/构建产物清理沿用 `Verification`，本条豁免。
- 不冲突 `safety-rules.md`：本条是动作安全，`safety-rules.md` 是数据安全，正交。

## 建议落地的规则文本

放进 `adapters/gate-source/shared/gate-core.md`，作为 `## Read And Write Boundaries` 之后的新小节：

```markdown
## File Deletion Safety

- 本条当前只针对 Windows 环境：删除项目源码、配置或用户文件/目录时，默认走系统回收站，不永久删除。非 Windows 环境暂不受本条约束。
- 禁止用 `rm`、`del`、`Remove-Item`、`rd`/`rmdir` 等绕过回收站的命令删除上述文件；Git Bash 下的 `rm` 同样永久删除，不得用于项目文件。
- 优先使用可进回收站的方式：先执行 `Add-Type -AssemblyName Microsoft.VisualBasic` 加载程序集，再调用 PowerShell 的 `[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteFile(..., 'OnlyErrorDialogs', 'SendToRecycleBin')` 与 `[Microsoft.VisualBasic.FileIO.FileSystem]::DeleteDirectory(..., 'OnlyErrorDialogs', 'SendToRecycleBin')`。无法确认某条删除命令是否进回收站时，先询问用户再执行。
- 例外：构建/测试/缓存等非交付产物的路径受限清理按 `Verification` 段规则处理，不受本条约束；`git clean`、`git rm`、`git checkout -- <path>`、`git reset --hard` 等 git 删除按 git 操作边界规则处理，仍需用户明确提及。
```
